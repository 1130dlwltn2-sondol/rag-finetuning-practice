# Part 3. LLM 파인튜닝

## 30. 파인튜닝이란 무엇인가

거대 언어 모델(LLM)은 웹과 책에서 모은 방대한 텍스트로 사전 학습(pre-training)된 모델이다. 파인튜닝(fine-tuning)은 이 사전 학습된 모델의 가중치를 특정 목적에 맞게 추가로 조정하는 작업이다. 처음부터 모델을 만드는 것이 아니라, 이미 훈련된 모델을 출발점으로 삼아 조금 더 가르치는 과정이라고 이해하면 된다.

이 장에서는 파인튜닝의 정확한 개념, 전체 학습과 무엇이 다른지, 그리고 무엇보다 중요한 질문인 파인튜닝이 정말 필요한 경우와 그렇지 않은 경우를 구분하는 기준을 다룬다. 파인튜닝은 비용과 시간이 드는 작업이므로, 시작하기 전에 판단 기준을 세우는 것이 실무에서 가장 중요하다.

### 파인튜닝의 개념

사전 학습된 LLM은 다음 토큰을 예측하는 방식으로 언어의 패턴을 배운다. 이 모델에 특정 형식의 질문과 답변 쌍을 반복해서 보여 주면, 모델은 그 형식과 도메인에 맞게 응답하는 방향으로 가중치가 미세 조정된다. 예를 들어 고객 상담 문답 1,000쌍을 학습시키면, 모델은 그 회사의 말투와 제품 정보를 반영한 답변을 내놓기 시작한다.

파인튜닝의 효과를 이해하려면 모델이 무엇을 바꾸고 무엇을 유지하는지 알아야 한다. 사전 학습에서 얻은 언어 이해 능력과 일반적인 지식은 그대로 두고, 특정 작업에 대한 응답 스타일과 도메인 적응만 조정하는 것이 파인튜닝의 목적이다. 그래서 데이터가 적어도(수백 개에서 수천 개 수준) 의미 있는 변화를 만들 수 있다.

### 전체 학습과의 차이

전체 학습(full fine-tuning)과 파인튜닝이라는 말이 혼용되기도 하지만, 실무에서는 두 가지를 명확히 구분하는 편이 좋다. 이 책에서는 다음과 같이 정리한다.

| 구분 | 사전 학습(처음부터 학습) | 파인튜닝 |
| 데이터 규모 | 수조 개 토큰 | 수백~수만 개 예제 |
| 학습 대상 가중치 | 전부 무작위 초기화부터 | 사전 학습 가중치를 출발점으로 |
| 필요 자원 | 수천 장의 GPU, 수개월 | 1~수 장의 GPU, 수시간~수일 |
| 목적 | 언어 능력 자체를 획득 | 특정 작업·형식·도메인에 적응 |

예전에는 전체 학습과 파인튜닝의 경계가 모호했지만, LoRA 같은 효율적 방법이 등장하면서 오늘날 실무에서 말하는 파인튜닝은 대부분 파라미터 효율적 파인튜닝(PEFT)을 의미한다. 자세한 방법은 32장에서 다룬다.

### 파인튜닝이 필요한 경우

다음 중 하나라도 해당하면 파인튜닝을 검토해 볼 만하다.

첫째, 출력 형식이 엄격하게 정해져 있을 때이다. JSON 스키마를 정확히 지켜야 하거나, 사내 보고서 양식처럼 고정된 구조로 답해야 하는 경우가 대표적이다. 프롬프트만으로는 형식이 가끔 깨지는데, 파인튜닝은 이 안정성을 크게 높인다.

둘째, 특정 말투나 톤을 일관되게 유지해야 할 때이다. 브랜드의 목소리, 고객 응대 매뉴얼의 어투처럼 반복적으로 같은 스타일을 내야 하는 작업에서는 파인튜닝이 효과적이다.

셋째, 도메인 특화 용어와 추론 패턴을 모델이 모를 때이다. 법률 조항 해석, 의료 기록 요약처럼 전문 용어와 그 분야의 사고방식을 함께 배워야 하는 경우이다. 다만 이 경우에도 새로운 사실을 가르치는 것보다는, 그 분야의 표현 방식과 추론 방식을 익히는 데 가깝다는 점을 기억해야 한다.

### 최후 수단 원칙: 프롬프트와 RAG를 먼저

파인튜닝은 최후의 수단으로 두는 것이 원칙이다. 비용이 들고, 잘못하면 모델의 기존 능력을 해치며, 한 번 학습한 지식은 쉽게 업데이트되지 않기 때문이다. 실무에서는 다음 순서로 시도한다.

1. 프롬프트 엔지니어링: 시스템 프롬프트와 지시를 다듬는 것만으로 해결되는지 확인한다. 비용이 거의 들지 않는다.
2. 퓨샷(few-shot) 예제: 프롬프트 안에 좋은 예시 몇 개를 넣어 형식을 유도한다.
3. RAG: 답에 필요한 지식이 외부 문서에 있다면 검색으로 가져와 맥락에 넣는다. 지식이 자주 바뀌는 경우에 특히 유리하다.
4. 파인튜닝: 위 방법으로 해결되지 않는 행동 변화가 필요할 때 마지막으로 시도한다.

흔한 실수는 파인튜닝으로 지식을 가르치려는 것이다. 모델이 모르는 최신 사실이나 사내 문서를 파인튜닝으로 주입하면, 학습 데이터에 없는 질문에는 여전히 환각을 일으키고, 학습한 사실도 맥락이 바뀌면 부정확해진다. 지식 전달은 RAG의 영역이고, 파인튜닝은 행동 방식을 바꾸는 도구라는 구분을 명확히 해 두자.

### 파인튜닝 용어 정리

이 책에서 쓰는 핵심 용어를 정리한다. SFT(Supervised Fine-Tuning)는 정답이 있는 예제로 지도 학습하는 파인튜닝이다. PEFT(Parameter-Efficient Fine-Tuning)는 LoRA처럼 일부 파라미터만 학습하는 효율적 방법들의 총칭이다. 정렬(alignment)은 모델의 행동을 사람의 선호와 가치에 맞추는 과정으로, DPO 같은 선호도 최적화가 여기에 속한다.

베이스 모델(base model)은 파인튜닝의 출발점이 되는 사전 학습 모델이다. 인스트럭션 튜닝이 된 모델(예: gemma-2-9b-it)은 이미 지시 수행 능력이 있어 파인튜닝의 출발점으로 좋다. 어댑터(adapter)는 LoRA처럼 베이스 모델에 얹는 작은 추가 가중치를 말한다.

### 학습 전 평가 베이스라인

파인튜닝을 시작하기 전에 반드시 현재 모델의 성능을 측정해 둔다. 이를 베이스라인이라고 한다. 베이스라인 없이 학습하면, 좋아진 것인지 나빠진 것인지 판단할 근거가 없다.

베이스라인 평가는 이렇게 준비한다.

- 평가용 질문 집합을 50~200개 정도 미리 만든다. 학습 데이터와 겹치지 않게 따로 보관한다.
- 각 질문에 대해 기대하는 답의 기준(정답, 채점 기준, 좋은 답의 예)을 정한다.
- 학습 전 모델의 답을 기록하고 점수를 매긴다.
- 학습 후 같은 질문 집합으로 다시 측정해 차이를 비교한다.

이 과정을 생략하면 "느낌상 좋아진 것 같다"는 주관적 판단에 의존하게 되고, 실제로는 특정 유형의 답변이 나빠지는 퇴행(regression)을 놓치기 쉽다. 35장에서 평가 방법을 자세히 다룬다.

### 평가 질문 설계 요령

베이스라인용 질문은 실제 사용 상황을 반영해야 한다. 고객 상담 모델이라면 실제 들어오는 문의 유형을 비율대로 섞는다. 쉬운 질문만 모아 놓으면 평가가 낙관적으로 나오고, 어려운 것만 모으면 비관적으로 나온다.

질문 유형을 몇 가지로 나눠 라벨을 붙여 두면 분석이 편하다. 예를 들어 사실 확인형, 절차 설명형, 불만 응대형처럼 나눈다. 학습 후에 어떤 유형이 좋아지고 나빠졌는지 보면, 데이터 보강이 필요한 영역이 보인다.

질문은 학습 데이터와 표현을 다르게 쓴다. 같은 문장을 그대로 쓰면 외운 것인지 이해한 것인지 구분할 수 없다. 의도는 같되 표현이 다른 질문으로 구성하는 것이 요령이다.

### 파인튜닝으로 할 수 없는 것들

파인튜닝의 한계를 정확히 아는 것도 중요하다. 첫째, 모델이 원래 할 수 없던 추론을 가르치기는 어렵다. 예를 들어 복잡한 수학 증명을 못하는 모델에게 증명 데이터만 보여 준다고 갑자기 잘하게 되지는 않는다. 파인튜닝은 기존 능력의 방향을 트는 것이지, 새로운 지적 능력을 심는 것이 아니다.

둘째, 학습 데이터에 없는 사실은 가르칠 수 없다. 파인튜닝으로 회사 제품 목록을 외우게 하려는 시도가 대표적이다. 학습 중에 본 문장은 그럴듯하게 뱉어내지만, 조금만 표현을 바꾸면 틀린 답을 내놓는다. 사실 전달이 목적이라면 RAG가 정답이다.

셋째, 한 번 학습한 내용을 선택적으로 지우기는 어렵다. 잘못된 패턴을 학습시켰다면 데이터를 고쳐 다시 학습하는 편이 낫다. 그래서 학습 전 데이터 검수(31장)가 중요한 것이다.

### 비용 감각 잡기

파인튜닝 비용은 크게 GPU 사용료와 데이터 제작비로 나뉜다. GPU 한 장(A100 40GB급 기준)으로 9B 모델 LoRA 학습 3에폭은 보통 몇 시간 안에 끝나며, 클라우드 기준으로 수만 원 수준이다. QLoRA를 쓰면 더 저렴한 GPU로도 가능하다.

진짜 비용은 데이터에 있다. 고품질 예제 1,000개를 사람이 직접 만들면 수일이 걸린다. 그래서 실무에서는 강한 모델로 초안을 생성하고 사람이 검수하는 하이브리드 방식을 많이 쓴다. 데이터 제작비를 줄이려고 품질을 타협하면 학습 자체가 무의미해지므로, 예산을 짤 때는 데이터 검수 시간을 반드시 포함한다.

### 따라 하기: 베이스라인 측정 스크립트 뼈대

학습 전후를 비교하는 평가 뼈대를 미리 만들어 두면 이후 장에서 바로 활용할 수 있다. 아래 코드는 질문 집합을 읽어 모델의 답변을 파일로 저장하는 간단한 예제이다.

```python
# baseline.py — 학습 전후 비교를 위한 답변 수집 스크립트
import json
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

MODEL_NAME = "google/gemma-2-9b-it"  # 사용할 베이스 모델로 교체
QUESTIONS_PATH = "eval_questions.jsonl"  # {"question": "..."} 형식의 파일
OUTPUT_PATH = "baseline_answers.jsonl"

tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

def answer(question):
    messages = [{"role": "user", "content": question}]
    prompt = tokenizer.apply_chat_template(
        messages, tokenize=False, add_generation_prompt=True
    )
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    with torch.no_grad():
        outputs = model.generate(
            inputs["input_ids"],
            max_new_tokens=256,
            temperature=0.0,  # 평가 재현성을 위해 0으로 고정
            do_sample=False,
        )
    return tokenizer.decode(outputs[0], skip_special_tokens=True)

with open(QUESTIONS_PATH, encoding="utf-8") as f, \
     open(OUTPUT_PATH, "w", encoding="utf-8") as out:
    for line in f:
        q = json.loads(line)["question"]
        result = {"question": q, "answer": answer(q)}
        out.write(json.dumps(result, ensure_ascii=False) + "\n")
        print("완료:", q[:40])

print("저장 완료:", OUTPUT_PATH)
```

이 스크립트를 학습 전에 한 번, 학습 후에 한 번 실행하면 두 답변 파일을 나란히 비교할 수 있다. 정량 점수(정답률 등)는 질문 집합의 성격에 맞게 별도로 계산한다.

### 파인튜닝을 결정하는 질문 다섯 가지

실무에서 파인튜닝을 시작하기 전, 다음 질문에 답해 본다.

1. 프롬프트와 예제만으로 해결할 수 있는가. 해결된다면 파인튜닝은 과하다.
2. 필요한 것이 지식이 아니라 행동 방식인가. 지식이면 RAG를 쓴다.
3. 학습 데이터 500개 이상을 확보할 수 있는가. 그 이하에서는 효과가 제한적이다.
4. 평가 기준이 명확한가. 무엇이 좋아진 것인지 정의할 수 있어야 한다.
5. 잘못 학습되었을 때 되돌릴 계획이 있는가. 체크포인트와 데이터 버전을 관리한다.

다섯 가지에 모두 답할 수 있으면 파인튜닝을 시작할 준비가 된 것이다. 하나라도 막히면 그 부분을 먼저 해결한다.

### 핵심 정리

- 파인튜닝은 사전 학습된 모델의 가중치를 특정 목적에 맞게 추가로 조정하는 작업이며, 처음부터 학습하는 것보다 훨씬 적은 자원으로 수행한다.
- 지식 주입보다 행동 방식(형식, 말투, 도메인 추론 패턴)을 바꾸는 데 적합하며, 새로운 사실 전달은 RAG의 영역이다.
- 프롬프트, 퓨샷, RAG를 먼저 시도하고 해결되지 않을 때 마지막 수단으로 파인튜닝을 선택한다.
- 학습 전 반드시 베이스라인을 측정해 두어야 학습 효과를 객관적으로 판단할 수 있다.
